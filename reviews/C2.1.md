## T2.1.1 reviewer amendment — Sass default precedence

The exact task configuration builds but fails its Vazirmatn verification: both Persian Bootstrap stylesheets use the shared system font stack. Quarto reverses theme variable sections, then applies the earlier base stylesheet's unconditional variable assignments over the later Persian/dark values. Thus the same defect also overwrites the intended dark palette.

Quarto documents this reversed variable ordering in its official “More About Quarto Themes” guide (`https://quarto.org/docs/output-formats/html-themes-more.html`), and the installed Cosmo theme uses `!default` declarations to allow this layering. The installed `/Applications/quarto/bin/quarto.js` function `mergeLayers` (around line 87524) explicitly reverses the default sections. The generated CSS confirms both the failed Persian font precedence and overwritten dark colors.

To finish the original T2.1.1, add `!default` immediately before the semicolon on every Sass variable assignment in the `scss:defaults` section of `shared/styles/base.scss`. Preserve the variable names/values and all rules exactly. Keep `dark.scss` and both theme arrays exactly as the task supplies them, with `rtl.scss` last. No other files or changes are authorized beyond the original task scope and report.

Rerun every original Verify command in order, record this amendment, and commit the completed original task. Reviewer will verify the actual computed font and light/dark colors in the browser. Do not weaken or skip the font check.
