## Goal
Create a project virtual environment `.venv/` with the packages needed to render posts and run site scripts.

## Background (read only)
- Quarto runs Python code cells through Jupyter. Later, the Makefile tells Quarto to use `.venv/bin/python`.
- Heavy ML packages such as torch are **not** site-level. Each post has its own requirements and its outputs are frozen.

## Files you may create or change
- `requirements.txt`
- `requirements.lock.txt`
- `.venv/` (ignored by git, so it isn't committed)

## Steps
1. Create `requirements.txt` with this **exact content**:
~~~text
# Site-level Python packages: used to render posts and to run scripts/.
# Heavy, post-specific packages (e.g. torch) are NOT listed here; post outputs are frozen.
jupyter
nbformat
nbclient
matplotlib
numpy
pyyaml
plotly
~~~
2. Run:
```bash
python3 -m venv .venv
```
```bash
.venv/bin/pip install --upgrade pip
```
```bash
.venv/bin/pip install -r requirements.txt
```
```bash
.venv/bin/pip freeze > requirements.lock.txt
```

## Do NOT
- Do not install anything outside `.venv/`.
- Do not add packages that aren't in the list.

## Verify
```bash
.venv/bin/python --version
```
```bash
.venv/bin/python -c "import yaml, numpy, matplotlib, plotly, nbformat, nbclient; print('imports ok')"
```
```bash
QUARTO_PYTHON=.venv/bin/python quarto check jupyter
```
```bash
git status --short
```

## Done when
- [ ] Python is 3.11 or newer
- [ ] `imports ok` is printed
- [ ] `quarto check jupyter` reports the `.venv` Python and Jupyter without errors
- [ ] `git status` shows only `requirements.txt` and `requirements.lock.txt` as new (no `.venv`)
