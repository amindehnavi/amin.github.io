# R3 — Technical proofread of an English post (report only)

| | |
|---|---|
| Milestone | M8 Operating mode (recurring) |
| Who | 🤖 AGENT — level **standard** |
| Inputs given by the Owner in the prompt | `SLUG` = full post folder name, e.g. `2026-12-self-attention` |
| Time | ~20 min |

## Goal
Find problems in the English post **without changing it**. The Owner decides what to fix.

## Files you may create or change
- **Only** `reports/R3-<SLUG>.md`. You must not edit the post.

## Steps
1. Read `en/posts/<SLUG>/index.qmd` (or `index.ipynb`) completely.
2. Run:
```bash
make render-en 2>&1 | tail -40
```
```bash
grep -n "TODO(owner)" en/posts/<SLUG>/index.*; echo "exit=$?"
```
```bash
grep -c -i "math input error\|undefined control sequence" en/_site/posts/<SLUG>/index.html; echo "exit=$?"
```
```bash
grep -n "Traceback\|Error" en/_site/posts/<SLUG>/index.html | head -20
```
3. Write the report with these sections (use the normal report template, and add these under "What I did"):
   - **Build problems:** render warnings or errors, code cells that raised errors, math that didn't render
   - **Leftovers:** `TODO(owner)`, empty sections, template text still present
   - **Language suggestions:** a table `| line | original | suggestion | reason |` for grammar, clarity and typos. At most 20 items, most important first
   - **Technical questions:** statements that look **possibly wrong or imprecise**, phrased as questions with the line number, e.g. "Line 42: is the scaling factor √d_k or d_k?" Never assert; ask
   - **Front matter:** are `description`, `categories`, `series`/`series-order` and `image` set sensibly? Does `description` work as a one-sentence summary?
   - **Terms:** English terms used in the post that are **not** in `shared/data/glossary.yml` (candidates to add)

## Do NOT
- Don't edit the post, the glossary or anything else.

## Done when
- [ ] Every report section above exists (write "None" where nothing was found)
