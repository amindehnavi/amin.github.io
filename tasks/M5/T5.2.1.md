~~~~markdown
# Prompt: translate an English post into Persian

You are translating a technical machine-learning blog post from English into Persian for Persian-speaking students and engineers.

## Inputs
- English post: `en/posts/<SLUG>/index.qmd`
- Glossary: `shared/data/glossary.yml`. Terms with `status: reviewed` are **mandatory**; `draft` terms are suggestions.
- Persian file to write: `fa/posts/<SLUG>/index.qmd` (it already exists from the template; replace its whole content)

## Keep EXACTLY as in English (never translate or change)
- Everything inside code blocks and code cells (```` ``` ```` … ```` ``` ````), including code comments.
- Cell option lines starting with `#|`, **except** the text of `fig-cap` and `fig-alt`, which you translate.
- All math: `$…$`, `$$…$$`, LaTeX environments.
- URLs, file and image paths, cross-reference labels (`@fig-x`, `{#eq-y}`, `{#tbl-z}`), shortcodes `{{< … >}}`, HTML tags and attributes, CSS classes.
- Front-matter **keys**, and these values: `date`, `categories`, `series`, `series-order`, `image`, `format`.
- Set `draft: true`.

## Translate
- Front-matter values `title` and `description`.
- All prose: headings, paragraphs, list items, quotes, table text (not numbers or code), callout texts and titles, image alt text, `fig-cap`.

## Style
1. Natural, clear, semi-formal Persian, like a good university textbook. Re-order sentences as Persian needs; never translate word by word.
2. Keep the meaning exact. Do not add, remove, or "improve" technical content. If the English is ambiguous, translate it faithfully and add `<!-- TRANSLATOR NOTE: … -->` on the line above.
3. Terminology: use the glossary `fa` term. On the **first** use in the post, add the English in parentheses: «توجه (Attention)». After that, use only the Persian term.
4. Terms not in the glossary: use the most common term in Persian ML writing, add English in parentheses on first use, and list them under **"New terms"** in your report.
5. Names of models, libraries, functions and datasets stay in English. Inside Persian sentences wrap them as `[PyTorch]{.ltr}`. Inline code stays in backticks.
6. Digits: Persian digits (۰–۹) in prose; Latin digits inside code, math, numeric tables and front matter.
7. Spelling: Persian `ی` and `ک` (never `ي` `ك`); use نیم‌فاصله (ZWNJ): «می‌شود»، «داده‌ها»، «شبکه‌های»؛ Persian punctuation «،» «؛» «؟» and quotes «».
8. The "واژه‌های این نوشته" table: column 1 English, column 2 Persian, using glossary terms.

## Final self-check (all must pass before you finish)
1. The number of lines starting with ```` ``` ```` is the same in the English and Persian files.
2. The number of `$` characters is the same in both files.
3. Front matter has `draft: true` and the same `date`, `categories`, `series`, `series-order` as English.
4. `.venv/bin/python scripts/lint_fa.py` reports no errors (E…) for this file, and you fixed every warning (W…) in prose.
~~~~
